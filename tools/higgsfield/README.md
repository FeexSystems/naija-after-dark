# NAAD × Higgsfield Asset Intake

This directory defines a controlled hand-off from Higgsfield to the existing Unity asset pipeline. It does **not** replace the existing Blender/Unity tooling or the canonical NAAD World Model.

## Pipeline

1. Generate in Higgsfield using the approved asset brief and record the generation job ID.
2. Export the source asset (prefer GLB for static meshes; use FBX where rig/animation interchange requires it).
3. Place the export in `tools/higgsfield/staging/`. Keep source files out of tracked Unity folders until they pass intake.
4. Add or update the asset record in `asset-intake.json`.
5. Run the validator:
   ```bash
   python tools/higgsfield/validate_intake.py
   ```
6. Resolve all validation errors. Record measured polygon count, texture dimensions, rig/animation status and a SHA-256 checksum.
7. Obtain and record license/usage evidence. Generated output is not considered cleared merely because it was generated by a connected service.
8. After approval, import through the Unity Editor/Unity CLI and run the existing NAAD model, scene and Android verification gates.

## Status lifecycle

- `planned`: brief exists; no exported file is expected.
- `generated`: Higgsfield job exists; export has not yet been staged.
- `staged`: source file is in the local staging folder.
- `validated`: technical checks and checksum are recorded.
- `approved_for_unity`: technical checks pass and rights evidence is recorded.
- `rejected`: do not import or use.

The validator is intentionally conservative. It does not infer license rights, rig quality, visual quality, or gameplay suitability from a filename. It does not automatically import or alter scenes.

## Existing assets first

The repository already has a 57-model NAAD content pack and an existing Blender/Unity pipeline. Review `game/unity/Assets/NAAD/Content/Models/naad_asset_manifest.json` and `naad_verify_report.json` before generating replacements. Higgsfield should fill documented gaps or create approved higher-quality variants, not create duplicate grills, vendors, street props or generic scenery.

## Asset naming and provenance

Use the existing NAAD grammar: `<CAT>_<Part>_<DISTRICT>_v<NNN>` and the category/district definitions in `tools/unity-asset-pipeline/naad_addon/rules.py`. Never rename existing vendor assets or regenerate Unity GUIDs to force a naming convention.

Each record must preserve:
- provider and generation job ID
- exact prompt/brief reference
- original export format and staged file path
- SHA-256 of the staged export
- target NAAD scene
- license status and evidence
- technical validation notes and measured stats
- explicit approval identity and timestamp before promotion

## Local staging and Git

Keep large exports local in `tools/higgsfield/staging/`; do not commit generated binaries by default. Commit the manifest, briefs, validation code and reports. Promote only reviewed assets into the Unity project using the normal Unity import flow, then commit the resulting assets and Unity-generated `.meta` files together.
